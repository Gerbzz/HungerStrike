# HungerStrike screenshot provenance

The README displays `docs/verification/desktop-kitchen-final.png`, an app-rendered 1440 × 900 frame from the October 10, 2026 Windows preview verification run. SHA-256: `E87D19A39B2B53405A29AF2DBCE5E8A8446F6E35B3F771324DA320143AD8D9BE`. The image shows synthetic kitchen inventory; it was visually inspected and is also linked from [verification.md](../verification.md). The receipt, meals, and spending images linked beside it come from the same run. No real receipt, client data, or personal file appears in the displayed kitchen frame.

This is a **historical preview image**, not a current-source acceptance screenshot. The retained capture binary's source differs from the public source checkpoint. The current public source was built offline on October 14 with `cargo build --offline --locked -p hungerstrike-rust-desktop -j 1` using an existing local target cache; the build completed in 26.44 seconds. That exact-source debug executable has SHA-256 `C8B26E6EC4C5791902246053DF3FA84B3CBE2F56A9CFEA9517A86BCC2BCB480C`.

An isolated run set `HUNGERSTRIKE_DATA_DIR` to a temporary workspace directory, used `HUNGERSTRIKE_CAPTURE_DEMO=kitchen`, and requested the app's `HUNGERSTRIKE_CAPTURE_PATH`. The executable exited with Windows code `0xC0000008` shortly after window creation, before writing a PNG. A second attempt with the DirectX 12 backend and a launch of the retained release binary ended with the same code. The exact cause was not established. The current source therefore has no verified screenshot from this session. The local synthetic database and launch logs were excluded from Git.

The earlier image shows the interface and original synthetic fixture, but does not verify that the current public source renders identically. The [verification record](../verification.md) describes tested behavior and limits; rendered frames do not prove native pointer or keyboard interaction, accessibility, or acceptance on other devices.
