# Local image OCR acceptance — 2026-10-10

These four inspected PNGs are **SYNTHETIC TEST DATA** generated from the fictional R001 grocery receipt. The target is six purchase lines (bananas, milk, eggs, pasta, spinach and dish soap), 1,741 cents subtotal, 28 cents fixture tax and 1,769 cents total. All prices and tax are invented test values, not current store prices or tax guidance. The tests invoked the app's Rust local OCR subprocess path with the installed English Tesseract, then parsed the returned text and exercised review/confirmation against in-memory SQLite. Text-fixture tests were not counted as image OCR evidence.

The same clean photo was read twice. After applying the same explicit review corrections, the second confirmation returned a duplicate outcome: receipt count stayed **1** and cash flow stayed **1,769 cents**. The app's cancel action cleared a pending image job and left scratch inventory empty.

The local subprocess timeout test used a deliberately stalled local process, not a claim that Tesseract itself stalled. It verified a 150 ms test timeout, cancellation, and child cleanup; production OCR uses a 15-second limit. Real retail photos, lighting, motion blur, paper folds, varied tax layouts, JPEG inputs, native file-dialog clicks and mobile cameras remain untested. The reviewed source text can be edited or discarded; no damaged result was silently confirmed.
